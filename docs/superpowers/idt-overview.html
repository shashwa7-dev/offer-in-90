IDT: from a daily timetable to a learning workspace

The same roadmap v3 content (7 tracks × 78 slots), delivered as weekly cycles of work items with estimates, on a real backend, in a new turborepo. Plane's ideas and UI, never its code, and every feature about learning.

What changes

The content stays. The way it's scheduled, stored and run changes.

Today: offer-in-90 retiring

  • Every task pinned to a clock time (05:15 DSA, 13:00 Systems…)
  • Routine form: wake-up, meals, gym, bedtime
  • Static site on GitHub Pages, data in the browser, Gist sync
  • News written by GitHub Actions into JSON files
  • One person, one plan, no login

New: IDT phase 1

  • Weekly cycles; items in recommended order, any order allowed
  • Every item has an estimate; unfinished work carries over
  • Next.js on Vercel, Neon Postgres, Google sign-in
  • News engine on Trigger.dev, stored in the database
  • Workspaces, members and roles ready (switched off for now)

How carry-over works

  1. On your first visit after a cycle ends (in your time zone), the app snapshots that cycle's stats, as Plane does on "transfer".
  2. Unfinished items move to the current cycle, marked "carried from Cycle 3". Cancelled items never move.
  3. Days you didn't open the app still get their daily items, so missed days pile up honestly.
  4. If work remains after the last planned week, "overtime" cycles are added until it's done.

Next.js + Vercel

Pages and server code in one app. Hobby plan is free for personal use; a public product later means Pro.

Neon + Drizzle

Postgres with a free tier, typed schema and migrations. Each preview deploy gets its own database branch.

Better Auth

Google only for now. Database sessions in an HTTP-only cookie, as Plane does. Sign-up limited to an allowlist.

Trigger.dev

Free plan ($5 of credit a month, 10 schedules). Set up like shopos's pro-backend-triggers. Vercel Cron is the fallback.

Docker for local

Postgres in Docker Compose for development and tests. No cloud account needed to run it.

Offline, as Plane

Show the last loaded data with an "Offline" banner, block edits, refetch on reconnect.

Roadmap releases

Plane seeds new workspaces from JSON files once. IDT adds stable ids and versions, so updates reach everyone without per-user work.

flowchart LR

packages/roadmap] --> B[Build + zod validation]
  B --> JSON["roadmaps/interview-2026/v15/*.json
committed to git"]
  JSON --> RV[(roadmap_version)]
  RV -->|new workspace| SEED[Seed rows,

  DIFF --> WS[Workspace rows]
  RV -->|admin: roll back| DIFF
  • Ids never change and are never reused. Removed items are marked retired.
  • An update adds new items, refreshes text and links, and skips any field you edited yourself. A deleted item never comes back.
  • Rollback uses the same rules in reverse. You see a one-time "What changed" note.

Jobs and time

Weekly news refresh

A Trigger.dev task calls a protected route; the engine fetches sources, uses the owner's model key, writes news, pulse and interview threads, and logs the run.

Daily reminder

"Today: 6 items · this cycle: 9 h left", in-app and by email through Resend for those who opt in. Phase 3.

Carry-over

No job at all. Runs on your first visit after the cycle ends, and is safe to run twice.

Time zones

Your IANA time zone, detected on first sign-in. "Today" and the Monday-to-Sunday cycle follow it, as Plane's user time zone does.

Progress, by estimate

Plane's burn-down counts completed items (or estimate points) per day over the cycle against an ideal line. IDT does the same in estimate minutes, adds the scope that carry-over brought in, and keeps the pace and forecast from today's app.

Security and AI keys

Checked on the server

  • Every read and write checks workspace membership and role
  • Allowlist enforced server-side
  • Admin app needs an instance_admin row
  • Job routes need the service token

Bring your own key, day 1

  • Setup › AI keys: provider + key, tested on save
  • Encrypted (AES-256-GCM), never sent back to the browser
  • Only the last 4 characters shown
  • The news engine alone uses the owner's key

Licence and data

  • Plane is AGPL: copy ideas, never code
  • Soft delete everywhere; account delete after 30 days
  • Neon point-in-time restore + JSON export
